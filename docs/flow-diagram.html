플로우 01 — 감상문 작성 + AI 추천 요청

사용자가 감상문을 작성하면 Spring Boot가 DB에 저장하고, 커밋 후 비동기로 FastAPI에 추천을 요청한다.

DB --> SP : saved (id)
SP --> FE : 201 { data: { id } }

플로우 02 — AI 추천 처리 + Polling + 재시도

FastAPI가 추천을 처리하고 Spring Boot에 콜백을 전송한다. 프론트는 polling으로 상태를 확인한다.

플로우 05 — AllAboutJazz 데이터 파이프라인

Airflow 3-DAG 파이프라인이 AllAboutJazz 리뷰를 수집하고, OpenAI Batch API로 요약/임베딩을 생성한 뒤 PostgreSQL에 저장한다.

DAG 1 — URL 수집 · 크롤링 · GPT Batch 제출

DAG 1 시퀀스
@startuml
skinparam backgroundColor #FAFAFA
skinparam sequenceArrowThickness 1.5
skinparam participantFontSize 13

participant "Airflow\nDAG 1" as DAG1
participant "PostgreSQL" as DB
participant "AllAboutJazz\n(Playwright)" as AAJ
participant "OpenAI\nBatch API" as OAI
participant "Slack" as SL
participant "DAG 2" as DAG2

DAG1 -> DAG1 : 수동 트리거

== check_pending_batch ==
DAG1 -> DB : SELECT pipeline_batches\n(status != completed)
DAG1 -> DB : SELECT crawl_jobs\n(미완료 job 필터링)
DB --> DAG1 : pending_batch / null

alt 미완료 batch 존재 (resume)
  DAG1 -> DAG1 : XCom에서 batch_id · job_ids 복원
else 신규 batch
  == create_batch ==
  DAG1 -> DB : INSERT pipeline_batches
  DB --> DAG1 : batch_num, batch_id

  == collect_and_register_urls ==
  DAG1 -> AAJ : URL 목록 수집 (Playwright)
  AAJ --> DAG1 : review URL[]
  DAG1 -> DB : UPSERT crawl_targets
  DAG1 -> DB : INSERT crawl_jobs\n(status=pending)
end

== crawl_details ==
DAG1 -> AAJ : 리뷰 상세 크롤링 (Playwright)
AAJ --> DAG1 : HTML 콘텐츠
DAG1 -> DB : INSERT allthatjazz_raw
DAG1 -> DB : UPDATE crawl_jobs\n(status → success | failed)

alt 성공률 < 80%
  DAG1 -> SL : 알림 전송
  DAG1 -> DAG1 : Task 실패
else 성공률 >= 80%
  == submit_gpt_batch ==
  DAG1 -> DB : SELECT allthatjazz_raw\n(batch 기준 필터)
  DB --> DAG1 : raw content[]
  DAG1 -> OAI : file upload
  OAI --> DAG1 : file_id
  DAG1 -> OAI : batch create
  OAI --> DAG1 : openai_batch_id
  DAG1 -> DB : INSERT processing_jobs\n(stage=gpt, openai_batch_id)
  DAG1 -> DAG2 : TriggerDagRunOperator\n{batch_id, openai_batch_id}
end
@enduml

check_pending_batch

방향테이블필드
READpipeline_batchesid, batch_num, status
READcrawl_jobsid, status, attempt_count (미완료 job 필터링)
XCom push—pending_batch → batch_num, batch_id, job_ids, pending_count (job_ids 길이, DB 컬럼 아님)

미완료 batch 존재 여부에 따라 resume_pending_batch 또는 create_batch로 분기한다. pending_count는 pipeline_batches 컬럼이 아니라 미크롤링 crawl_jobs 수를 계산한 임시값이다.

create_batch

방향테이블필드
INSERTpipeline_batchesid, batch_num, airflow_dag_run_id, status

반환값: { batch_num, batch_id } → XCom으로 다음 task에 전달

collect_and_register_urls

방향테이블필드
READAirflow Variablecurrent_start_page
READ (외부)AllAboutJazz리뷰 URL 목록 (HTML 파싱)
UPSERTcrawl_targetsurl, source
INSERTcrawl_jobsbatch_id, url, status='pending'
INSERT (실패시)error_historystage, batch_id, error_type, error_message, http_status_code

반환값: { batch_num, batch_id, url_count, end_page }

crawl_details

방향테이블필드
READcrawl_jobsid, batch_id, url, status='pending'
READ (외부)AllAboutJazz리뷰 상세 HTML (Playwright)
INSERTallthatjazz_rawcrawl_job_id, content, metadata
UPDATEcrawl_jobsstatus → 'success' | 'failed'
INSERT (실패시)error_historystage, batch_id, error_type, error_message

성공률 < 80% 이면 Slack 알림 후 Task 실패. 반환값: { batch_num, batch_id, success_count, failed_count }

submit_gpt_batch

방향테이블필드
READallthatjazz_rawid, content, crawl_job_id (batch 기준 필터)
WRITE (외부)OpenAI Batch APIfile upload → file_id, batch create → openai_batch_id
XCom push—openai_batch_result → openai_batch_id, file_id, item_count (재시도 중복 방지용)
INSERTprocessing_jobsbatch_id, stage='gpt', openai_batch_id, item_count, file_id

재시도 시 XCom에 openai_batch_id가 있으면 OpenAI 재요청 없이 DB INSERT만 재시도. 완료 후 DAG 2 트리거.

DAG 2 — GPT 결과 처리 · Embedding Batch 제출

DAG 2 시퀀스
